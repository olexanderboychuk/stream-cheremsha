# Soundpad (tab 11)

Instant sounds for streaming: hotkey-triggered playback, categories, waveform cards, and a MyInstants **Library** (browse → preview → add).

## Key files

| Symbol | File | Responsibility |
|--------|------|----------------|
| `SoundpadStore` | `src/stream_cheremsha/soundpad/store.py` | QSettings-backed entries; `library_dir`; `resolve_library_path()` copies into `<AppData>/soundpad/sounds/` |
| `SoundpadAudioEngine` | `src/stream_cheremsha/soundpad/engine.py` | Playback modes (restart/overlap/replace/queue/hold), cooldowns, ducking; preview via `play_preview()` / `stop_preview()` (sink key prefix `soundpad-preview:`) |
| `GlobalHotkeyManager` + backend | `src/stream_cheremsha/soundpad/hotkeys.py` | `ComboHotkeyBackend` shared state machine (press matching, 50 ms release debounce); `PynputHotkeyBackend` (X11 listener), `FakeHotkeyBackend` for tests |
| `MyInstantsClient` | `src/stream_cheremsha/soundpad/myinstants.py` | Rate-limited (≥1.2 s between requests) MyInstants fetcher; `fetch_trending(page)` uses the country-free base URL `/en/trending/` (site geo-redirects to the visitor's index); bounded caches: trending LRU ≤32 pages / TTL 600 s, MP3 disk cache ≤128 files & ≤256 MB with atomic writes |
| `ensure_x_authority` | `src/stream_cheremsha/x11_auth.py` | Self-heals stale-hostname `$XAUTHORITY` entries before pynput import (shared with actions keystroke simulation) |
| `SoundpadQmlApi` | `src/stream_cheremsha/ui/soundpad_qml_api.py` | QML bridge: grid CRUD + library slots (`openLibrary`, `loadLibraryPage`, `previewSound`, `stopPreview`, `addLibrarySound`) + preview state props (`previewPlayingId`, `previewLoadingId`) + l10n (`strings` view map over `_VIEW_L10N_KEYS`, `libraryStrings`, `tr()`, `set_locale()`) |
| `SoundpadView.qml` / `components/SoundpadLibraryPanel.qml` | `src/stream_cheremsha/qml/` | UI; library modal via `CheremshaModal` (`preferredWidth: 780`) |

## Invariants & decisions

- **Lazy everything**: the soundpad stack is built only on first tab open (`MainWindow._soundpad_api_lazy`, called from `_bind_qml_context_properties`); never in `_build_ui`.
- **curl_cffi stays a lazy import** inside `myinstants.py` (module `__getattr__`) — Chrome TLS impersonation to get past Cloudflare; must not appear in startup imports.
- **Library adds are copied into the store dir** (`resolve_library_path`) so bounded cache eviction can never break an added sound. The MP3 cache is disposable by design.
- **Library browsing is country-free**: we request the base `/en/trending/` URL (page N: `?page=N`) and let the site geo-redirect it to the visitor's country index — no locale→language mapping in our code; each user gets their own country's sounds. Out-of-range pages 404 → API error state.
- **l10n**: `l10n.tr()` raises `KeyError` on unknown keys — API slots catch and fall back to the key itself. Only UI chrome is translated: category names ("Меми", …) and playback modes are persisted data, stored as-is and never run through `l10n.tr()`. The "All categories" chip translates a display-only label over the internal `"__all__"` sentinel (`SoundpadView.allCat`), so filtering/matching logic stays locale-independent.
- **Reactive l10n pattern**: QML binds `spApi.strings.<key> || "<uk fallback>"`; parameterized text uses template + `.replace("{n}", …)` — slot calls in bindings do NOT re-evaluate on locale change, which is why both maps (`strings`, `libraryStrings`) are plain QVariantMaps re-read via `stringsChanged` when `set_locale()` fires.
- **Preview** uses sink dedupe-key prefix `soundpad-preview:`; a cancelled preview must NOT emit `previewFinished`. The API connects `previewFinished` → clears `previewPlayingId` (button auto-reverts to play). `previewLoadingId` tracks the in-flight resolve/download and is cleared on start/failure/stop; each new request bumps `_preview_seq`, so superseded jobs never set state or play.
- QML collections are exposed as JSON strings (`soundsJson`, `libraryRowsJson`) — codebase convention, not QVariantList.
- **X auth self-heal**: pynput connects to X at *import* time and python-xlib matches the xauth cookie by exact hostname; some sessions ship `$XAUTHORITY` entries keyed by a stale host (Qt tolerates this, pynput does not). `x11_auth.ensure_x_authority()` must run before every pynput import — it copies the file to `~/.cache/cheremsha/xauth`, appends `<hostname>/unix:0` reusing an existing MIT-MAGIC-COOKIE-1 (source file never modified), and points XAUTHORITY at the copy. Called from hotkeys grab, actions keystroke simulation, and `tests/conftest.py`.
- **HOLD is RESTART-with-repeat**: a press with the key not held (told apart from auto-repeat echoes by the held flag) stops strays for that id first, then arms and plays — every tap reliably (re)starts, never waits behind leftovers. Held-key re-fires during an active loop are no-ops (the engine repeats itself while `_held`); X11 re-fires at ~30x/sec must never stop/restart a live loop. Release disarms *and* cuts promptly, like RESTART. `duckingChanged` is change-guarded (`_set_ducking`) so overlapping sounds don't re-apply the music dip (each emit = an mpv IPC task).
- **HOLD never waits on cooldown (push-to-talk invariant)**: `SoundpadAudioEngine._play_impl` and `_on_hotkey_pressed` bypass `can_play()` for HOLD entirely — a configured 1–2 s cooldown otherwise delays the first audible output by seconds while the key is held (re-fires just retry into the same cooldown). Other modes still respect cooldown.
- **Press path does no blocking I/O**: `SoundpadQmlApi.playSound` serves audio from an in-memory cache (`_audio_cache`, validated by mtime/size, preloaded via `preloadHotkeyAudio()` on tab open) and defers the play-count QSettings flush via `QTimer.singleShot(0)` so the spawned audio task runs first. Only a cache miss touches disk on the GUI thread.
- **warmup primes the media pipeline**: `SoundpadAudioEngine.warmup()` creates the QMediaPlayer pool *and* plays a ~200 ms inaudible WAV through the SFX pool (first `setSource` + output-stream start), so neither the backend creation nor the FFmpeg/PipeWire first-play cost ever sits between a hotkey press and audible output. The silent-play step needs a running loop (it's skipped otherwise); player creation still happens either way.
- **Hotkey input is XGrab-first**: `XKeyGrabBackend` passive grabs (server-side delivery, immune to XRecord stream stalls) preferred; `PynputHotkeyBackend` (X11 RECORD listener) is a per-combo fallback via `GlobalHotkeyManager(fallback_backend=…)` (also covers multi-main combos XGrab cannot express); `FakeHotkeyBackend` last. `MainWindow._soundpad_api_lazy` probes each with an `F24` grab. Both real backends share the fire path (press matching, 50 ms release debounce, 2 s stale-flag bound so a lost release never eats the next press).
